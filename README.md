# 🐟 闲鱼智能搜索助手

输入**关键词 + 收货地址**，自动搜索闲鱼，按**性价比**把商品排好序，逐条给出**五星推荐分**和**中文推荐理由**——帮你从海量二手信息里快速找到值得买的那个。

> 招新作品 · 设计思路与实现过程见下文「设计与实现」章节

## ✨ 功能一览

- **一键智能搜索**：输入关键词 + 收货城市/区县，自动搜索闲鱼并抓取商品详情、卖家主页数据
- **五星性价比评分**：每个商品按 7 个维度加权打分（百分制 → 五星），并生成人话推荐理由
- **卖家甄别**：个人卖家优先；主页商品多、品类单一（职业商家）自动降权
- **品相解析**：从文案识别 全新 / 99新 / 95新 / 9成新 / 8成新 / 战损
- **同款比价**：同款商品按标题聚类，价格明显高于均价的自动扣分
- **私聊问价识别**：未标价的商品单独标记，不混入比价
- **自提估算**：从文案提取自提位置，同区 ≈3km / 同城 ≈15km / 跨城 ≈40km，纳入性价比
- **僵尸卖家降权**：超过 10 天未上线的卖家标记「不推荐」，固定排在最后
- **多种排序**：综合性价比 / 价格最低 / 距离最近 / 品相最新
- **降级演示模式**：闲鱼反爬导致真实抓取失败时，自动切换内置仿真数据，保证演示永远能跑通（页面有明确标注）

## 🚀 运行方法

```bash
# 1. 安装依赖（Python 3.10+）
pip install -r requirements.txt
python -m playwright install chromium

# 2. 启动
npm run dev          # 等价于 python -m uvicorn backend.app:app --port 7100

# 3. 浏览器打开 http://localhost:7100
```

使用步骤：

1. 点击「打开闲鱼网页并登录」→ 在弹出的浏览器窗口里扫码登录闲鱼（登录态只保存在本机 `browser_profile/`，不会上传）
2. 输入关键词、收货城市/区县 → 点「智能搜索」
3. 等待分析完成（首次约 1-4 分钟），按推荐列表逐个看理由、跳闲鱼下单

> 不登录也能搜（结果可能不全，部分接口会拒绝访问）。

## 🧠 设计与实现

### 1. 需求分析（真实使用痛点）

闲鱼搜索有三个痛点：结果里混着大量职业商家和僵尸卖家；同款商品价格差异大但只能逐条点进去比价；自提、问价等信息藏在文案里，扫一眼根本注意不到。本工具把「挑货」的隐性经验显式化成可计算的规则。

### 2. 架构

```
浏览器(前端 static/)  ──HTTP──►  FastAPI(backend/app.py)
                                     │
        ┌────────────────────────────┼──────────────────────────┐
        ▼                            ▼                          ▼
  backend/scraper.py          backend/scorer.py          backend/mock_data.py
  Playwright 有头浏览器        7 维加权打分 + 排序          演示数据(降级模式)
  拦截 mtop 接口拿 JSON
```

**关键决策：**

- **登录态方案**：用 Playwright 的「持久化上下文」启动有头 Chromium，用户手动登录一次，Cookie 保存在本地目录复用——因为闲鱼没有公开 API，搜索接口不登录会被反爬（实测返回 `RGV587_ERROR`）。
- **不解析 DOM，改拦截接口**：闲鱼前端改版频繁，DOM 类名随时会变；而前端总要调自家的 mtop JSON 接口。通过 `page.on("response")` 拦截搜索/详情/卖家页接口，直接拿结构化数据，健壮性好得多。
- **全链路容错**：字段缺失记 `None`，由评分模块降级为中性分 + 提示语；完全抓不到就抛异常，上层捕获后切换演示数据。评委演示不会翻车。

### 3. 评分模型（百分制 → 五星）

| 维度 | 权重 | 说明 |
|---|---|---|
| 价格 | 30 | 同款聚类后与组内中位价比价：≤0.8 倍满分，≥1.2 倍重扣 |
| 品相 | 20 | 文案关键词解析（全新 1.0 → 战损 0.3，未标注按 0.6 中性并提示） |
| 卖家信誉 | 15 | 好评率 × 评价数量系数 |
| 个人卖家 | 10 | 在售 ≤15 件或类目 ≥3 → 个人；≥50 件且品类单一 → 商家重扣 |
| 文案质量 | 10 | 文案长度 + 图片数量 |
| 自提距离 | 10 | 同区/同城/跨城三档，免运费加分、跨城交通成本扣分 |
| 上线时间 | 5 | 今天 1.0 → 10 天以上 0 并标记「不推荐」，**排序固定垫底** |

「私聊问价」商品价格维度记 0 分并说明「未计入比价」。每条商品输出 `+加分 / −减分 / ·提示` 三类中文理由，五星 = 百分制 ÷ 20。

### 4. 开发中遇到的问题与解决

1. **无头浏览器被风控**：实测 headless Chromium 访问闲鱼直接返回「非法访问，请使用正常浏览器」。→ 改用有头模式 + 关闭自动化特征开关，并让真人登录建立信任态。
2. **登录状态误判**：`personal_page` 未登录时返回 404 而非跳转登录页，最初按 URL 判断登录会误判。→ 改判闲鱼自己的 `loginuser.get` 接口返回（`SESSION_EXPIRED` = 未登录）。
3. **「私聊问价」打爆 JSON 序列化**：问价商品排序键用了 `float('inf')`，FastAPI 序列化报错。→ 排序键统一用 `10**12` 哨兵值。
4. **商家判定误伤**：仅按「在售数量」会把 20 件左右的普通卖家误判为商家。→ 结合类目多样性三档判断（商家 / 可能半职业 / 个人）。

## ⚠️ 已知限制

- 闲鱼接口无公开文档，页面改版可能导致个别字段解析失效——容错设计下评分会退回中性分并提示，不会崩溃
- 自提距离是城市/区县级粗估（未接地图 API），仅用于相对比较
- 「最近上线时间」只有卖家主页可见时才能获取，取不到时不扣分只提示

## 📁 目录结构

```
├── backend/
│   ├── app.py        # FastAPI 入口：静态页面 + REST API + 降级逻辑
│   ├── scraper.py    # Playwright 登录控制与闲鱼数据抓取（接口拦截式）
│   ├── scorer.py     # 7 维评分、推荐理由生成、排序
│   ├── mock_data.py  # 演示数据（真实抓取失败时自动启用）
│   └── models.py     # 数据结构约定
├── static/           # 前端页面（原生 HTML/CSS/JS）
├── scripts/dev.js    # npm run dev 启动脚本
├── requirements.txt
└── package.json
```
